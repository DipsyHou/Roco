# 战斗机制说明

本文档用于统一说明战斗流程、行动规则、伤害结算与局外养成规则。除特别注明外，文中的“回合”均指精灵自身的**正常回合**。

---

## 1. 战斗形态

本作采用 **5v5 时间轴战斗**。

- 每只精灵依据**速度**与**行动路程**决定下一次出手时间。
- 技能的施放通常消耗**队伍能量**，少数技能消耗精灵自身资源。
- 战斗中可能出现**正常回合**与**额外行动**两类出手机会。

---

## 2. 胜利条件

当一方场上所有精灵全部倒下时，另一方获胜。

---

## 3. 行动与回合

### 3.1 行动

**行动**是一次出手机会，分为：

- **自然行动**：精灵在自己的正常回合中获得的行动机会。
- **额外行动**：由技能、被动或其他效果插入的额外出手机会。

自然行动可选择的基础操作通常为：

- 普通攻击
- 使用技能
- 聚能

其中，普通攻击不消耗队伍能量；聚能通常会使全队能量增加 3 点。

额外行动在未特别说明时，也可选择：

- 普通攻击
- 使用技能
- 聚能

部分额外行动会附带额外限制，例如仅允许释放特定技能，或仅允许跳过。

### 3.2 回合

当精灵的行动值降为 0 时，将进入该精灵的正常回合。一个正常回合通常包含以下阶段：

1. 回合开始阶段
2. 正常行动执行阶段
3. 回合结束阶段

技能文案中的“**N 回合**”，通常指该精灵自身接下来的 **N 次正常回合周期**，而不是全场共享的大回合。

### 3.3 正常行动与额外行动的区别

- **正常行动**：时间轴轮到该精灵后，完整经历“回合开始 → 正常行动 → 回合结束”的流程。
- **额外行动**：插入在正常回合之外的出手机会，**不视为一个回合**。

---



## 4. 行动路程、行动值与时间轴



### 4.1 行动路程

每只精灵都有一个抽象属性，表示“距离下一个回合还有多远”，称为**行动路程**。

当轮到某只精灵的正常行动时，时间会向前推进，该精灵会立刻获得下一回合的行动路程。

为了支持行动提前与延后，即使当前正在行动的精灵，也始终保有其下一回合的行动路程。

### 4.2 行动值

**行动值**的计算公式为：

```text
行动值 = 行动路程 ÷ 速度
```

其中速度至少为 1。

- **行动值越小，越先行动**。
- 时间轴根据行动值决定下一名行动者。
- 当行动值相同时，按速度、入场顺序等内部规则继续比较。
- 界面上的行动条仅用于预测后续行动顺序，不改变实际战斗状态。



### 4.3 时间轴推进

当某精灵的**正常回合**首次开始进入执行时：

1. 按该精灵当前的行动值推进全场时间。
2. 为该精灵挂上“下一圈”的标准行动路程。



### 4.4 行动提前与延后

- **提前 X%**：当前行动路程减少 `10000 × X%`，最低降至 0。
- **延后 X%**：当前行动路程增加 `10000 × X%`。

---



## 5. 额外行动

额外行动是自然行动之外的出手机会，具有以下特性：

- 不推进时间轴
- 不改变行动路程
- 不触发仅限正常回合的“回合开始 / 回合结束”结算

如果队列中存在额外行动，则由额外行动队列中的精灵依次执行操作。精灵在额外行动中通常可以像正常轮到自己时一样选择操作。

### 5.1 额外行动队列

多个额外行动按照队列顺序依次执行：

- 后触发的额外行动通常排在后面，例如队友按队伍编号依次出手。
- 部分效果会插入到队列最前方，例如牌技连锁。



### 5.2 额外行动与眩晕

- **正常行动**：若在回合开始时处于眩晕状态，则本回合的正常行动被跳过，但仍会进入回合结束结算；眩晕层数会在回合结束时减少。
- **额外行动**：若执行前处于眩晕状态，则整个额外行动直接跳过，不执行任何操作。



### 5.3 额外行动的插入时机

条件触发的额外出手机会，例如招架、共舞、牌技连锁，均通过**额外行动**实现。按相对正常回合与队列的位置，常见插入时机有三类：

#### 回合开始后、正常行动前

若在**回合开始阶段**插入额外行动（例如巴哈姆特拥有「招架」时），则应：

1. 完成当前精灵的回合开始结算。
2. 依次结算队列中的所有额外行动。
3. 返回当前精灵，再执行正常行动，随后进入回合结束。



#### 正常行动后、回合结束前

若在**正常行动执行过程中或刚结束后**插入额外行动（例如共舞、首次牌技连锁），则应：

1. 暂停当前精灵的回合结束。
2. 依次结算队列中的所有额外行动。
3. 返回当前精灵，完成回合结束并推进时间轴。



#### 额外行动后

额外行动本身也可以再插入后续额外行动（例如牌技连锁：占卜 / 揭晓 / 逆位结算后再次插队）。此时：

1. 当前这笔额外行动结算完毕后，新插入的条目进入同一队列（可插到队首或队尾，见 5.1）。
2. 在返回被暂停的正常回合之前，继续按队列顺序结算后续额外行动。
3. 队列清空后，再回到原先暂停处（正常行动或回合结束）。

同一额外行动队列中可以串联多种来源；上述时机也可能组合出现在同一次正常回合中（例如先结算回合开始插入的额外行动，再出手，再在行动后或连锁中继续插入）。

## 6. 队伍能量

- 队伍共享一条能量条。
- 默认开局能量为 **10**，上限为 **10**。
- 部分效果可以提高能量上限。
- 技能标注的能量消耗，从全队能量中扣除。
- 部分精灵使用个人资源（如秘能）替代队伍能量。
- 部分效果可动态改变某技能的显示消耗与实际消耗。

---



## 7. 能力值计算

物攻、魔攻、物防、魔防、速度均按**有效值**参与计算：

```text
有效值 = max(基础值 × 20%, 基础值 × (1 + 百分比加成合计) + 固定值合计)
```



### 7.1 计算规则

- 百分比加成来自各类能力上升/下降效果，按加算处理。
- 固定值在百分比计算后再进行加减。
- 部分被动与光环可额外提供百分比加成。
- 有效值为**浮点数**，参与伤害、速度等计算时不取整。
- 界面显示时可四舍五入为整数。



### 7.2 生命值说明

- 当前生命与生命上限不使用上述公式。
- 生命上限可以被效果或技能直接改变。

---



## 8. 能力值转化

部分效果会按某方能力值的一定比例，为其他精灵或自身提供能力值加成，这类效果称为**转化**。

### 8.1 默认规则

转化额度默认按**当前有效能力值**实时计算，除非文案说明使用快照。

### 8.2 不可二次转化

由转化效果提供的那部分能力值，**不计入任何转化效果的计算底数**。

计算转化底数时，应使用排除所有转化类加成后的有效值，但仍然包含：

- 装备提供的加成
- 非转化类百分比加成
- 非转化类固定加成

---



## 9. 伤害分类



### 9.1 按伤害类型


| 类型     | 说明          |
| ------ | ----------- |
| 普通攻击伤害 | 普攻造成的伤害     |
| 技能伤害   | 技能造成的攻击段伤害  |
| 附加伤害   | 附加在其他攻击上的伤害 |
| 持续伤害   | 中毒、灼烧等      |
| ...    | ...         |


攻击伤害是**普通攻击伤害、技能伤害和附加伤害**的统称。

### 9.2 按伤害属性


| 属性   | 说明  |
| ---- | --- |
| 物理伤害 | -   |
| 魔法伤害 | -   |
| 固定伤害 | -   |


不同属性伤害主要体现在计算方式不同。

## 10. 发动攻击

**发动攻击**指一次会打出伤害段的对敌出手，包括：

- 普通攻击
- `SkillDef.launches_attack = True` 的技能

这类出手通常满足以下规则：

- 发动目标在出手时进行快照。
- 一次出手只计为 **1 次发动攻击**。
- 多段技能仍然只算 1 次发动攻击。
- 相关效果在该次出手自身的伤害段结算之后触发，例如共振的附加伤害会在队友伤害之后结算。

无伤害倍率的技能不算发动攻击。
附加伤害不视为新的发动攻击。

---



## 11. 附加伤害

**附加伤害**在数值结算上与普通伤害一致，可按物理、魔法或固定伤害等类型进入相同的增减伤流程。

唯一差异是：**附加伤害不视为发动了一次攻击**，因此不会触发“发动攻击”相关效果。

---



## 12. 受击段

**一段伤害**指对同一受击者的一次完整伤害结算。

- 多段攻击彼此独立结算。
- 多目标攻击彼此独立结算。
- 各类持续伤害彼此独立结算。

它们之间互不影响。

---



## 13. 暴击

每一段伤害都会单独进行暴击结算，并拥有：

- **暴击率**
- **暴击伤害**



### 13.1 默认值

- 默认暴击率：**0%**
- 默认暴击伤害：**100%**

因此，若没有额外提升暴击率的效果，多数伤害都不会触发暴击。

### 13.2 基础值

**基础值**指尚未经过增减伤处理的伤害数值。

- 物理/魔法伤害：通常为“攻击方数值 × 100 ÷ 受击方对应防御”
- 攻击方数值由技能倍率与能力值共同决定，例如 100% 物攻
- 固定伤害的基础值为技能给定的数值



### 13.3 暴击率

- 默认 0%
- 可由效果与被动提高
- 按加算处理
- 上限为 100%
- 多段伤害的每一段分别独立判定



### 13.4 暴击伤害

- 默认 100%
- 表示暴击时基础值保持不变
- 可通过效果与被动按**百分点**提高
- 例如 +50 后变为 150%，即暴击时基础值 × 1.5



### 13.5 判定流程

1. 按暴击率进行随机判定。
2. 若判定成功，则基础值乘以暴击伤害倍率。
3. 若判定失败，则基础值保持不变。
4. 之后再进入后续增减伤流程。

---



## 14. 伤害计算顺序

对每一段伤害，按以下顺序结算：

1. **基础值**：物理/魔法伤害先进行防御换算；固定伤害使用技能给定值。
2. **暴击**：按本段暴击率判定，成功则基础值乘以暴击伤害倍率。
3. **攻方增减伤**：先百分比，再固定值；按物理/魔法/固定分类加算。
4. **防方百分比减伤**：包含效果、被动、抗逆等；每层抗逆减少 20% 减伤，并在本段中消耗 1 层抗逆。总减伤上限为 80%。
5. **防方固定减伤**：包含效果、队友光环，以及部分精灵被动提供的固定值减免（如灵珏）。同类加算；个别被动可改写与其他固定减伤的并存关系，或在减免时附带叠层等副作用。
6. **限伤**：若同时存在多个“单次伤害上限”，取限制最严格的一条。
7. **取整**：最终伤害不小于 0；即使最终伤害为 0，仍可能计为一次受击，命中、叠层等效果仍可能触发。

---



## 15. 扣血与死亡

根据上述结果扣除生命值。

- 部分被动可以在致死时改写结果，例如续命、复活。
- 确认死亡后，触发倒下与胜负判定。
- 即使伤害结算为 0，仍会派发受击事件（如 `on_damage`、`on_attack_hit` 等）。
- 各类被动应自行判断是否响应 0 伤害。

## 16. 效果分类

状态栏中的效果分为以下三类：

- **正面**：`[buff]`
- **负面**：`[debuff]`
- **状态**：`[state]`

---



## 17. 效果持续时间与层数

- “**持续 N 回合**”通常指携带者**正常回合结束**时减少 1。
- 层数按照各效果自身规则增减，不会每回合自动减少 1。
- 未写持续时间的效果视为永久。
- 未写可叠加的效果视为不可叠加。
- 显示规则见 `roco/core/battle/effect_display.py`。

---



## 18. 目标与场地

场上精灵按**队伍编号（槽位）**站位。

### 18.1 相邻判定

“相邻”指同队存活精灵按槽位编号排序后，左右紧邻的单位。

例如：1、5 号中 4 号阵亡时，攻击 3 号会向相邻目标扩散至 2 号与 5 号。

### 18.2 目标范围

技能说明中的目标类型决定可选目标范围。

---



## 19. 特殊技能

**特殊技能**指无法在回合内的正常行动中使用的技能。

## 20. 精灵能力值

每只精灵的以下六项能力分别对应一个**挡位**：

- 生命
- 物攻
- 魔攻
- 物防
- 魔防
- 速度



### 20.1 挡位含义

- 挡位决定该维度的**基础数值**。
- 局内 buff / debuff 仍按[能力值计算](#能力值计算)在基础值之上结算。

同一只精灵的六维可以处于不同挡位，例如物攻 5 档、魔攻 1 档，用于表达定位差异，而不是对六个数值做独立微调。

### 20.2 挡位表

物攻、魔攻、物防、魔防、速度共用同一套挡位数值；生命单独一套，步长更大。


| 挡位  | 生命  | 物攻 / 魔攻 / 物防 / 魔防 / 速度 |
| --- | --- | ---------------------- |
| 1   | 500 | 100                    |
| 2   | 550 | 110                    |
| 3   | 600 | 120                    |
| 4   | 650 | 130                    |
| 5   | 700 | 140                    |
| 6   | 750 | 150                    |


- 生命每档 +50，范围 500～750。
- 其余五维每档 +10，范围 100～150。



### 20.3 说明与边界

- 统一刻度后，配置时只需记录“该维是第几档”。
- 装备养成会在挡位基础上叠加，见[局外养成 - 装备系统](#21-局外养成---装备系统)。
- 挡位表为设计标定；旧模板会向最近一档取整。
- 新精灵只从表中取值，不再填写任意六维数值。

## 21. 局外养成 - 装备系统（待实现）

局外为每只精灵配置 **4 件装备**：

- 头饰
- 护甲
- 鞋子
- 武器



### 21.1 基本规则

- 每件装备只提供**固定值**能力加成。
- 装备不提供百分比加成。
- 装备不提供技能。
- 进入战斗时，装备与[挡位基础](#20-精灵能力值)合并，形成开局面板。



### 21.2 词条结构

每件装备包含：

- **3 条初始词条**
- **3 次升级机会**

因此，四件装备合计：

- **12 条初始词条**
- **最多 12 次升级**



### 21.3 词条种类

六种能力各有一种固定加成词条，且**同一件装备内词条种类不可重复**；不同装备之间可以重复。


| #   | 词条  | #   | 词条  |
| --- | --- | --- | --- |
| 1   | 生命  | 4   | 物防  |
| 2   | 物攻  | 5   | 魔防  |
| 3   | 魔攻  | 6   | 速度  |




### 21.4 初始词条生成

每件装备按顺序生成 3 条词条。

#### 第 1 条：由部位决定类型，品质随机


| 部位  | 第 1 条类型         |
| --- | --------------- |
| 头饰  | 生命              |
| 护甲  | 物防 **或** 魔防（随机） |
| 鞋子  | 速度              |
| 武器  | 物攻 **或** 魔攻（随机） |




#### 第 2、3 条

从上述 6 种词条中随机抽取，但必须排除本件装备已经拥有的种类。

例如：

- 武器第 1 条若为物攻，则第 2、3 条从生命、魔攻、物防、魔防、速度中抽取。
- 第 2、3 条不限定于该部位的默认词条范围。

每条词条生成时，都会独立随机品质档：

- 绿
- 蓝
- 紫
- 金



### 21.5 词条数值

词条在生成或升级时，从对应品质档取数。


| 词条                     | 绿    | 蓝    | 紫    | 金    |
| ---------------------- | ---- | ---- | ---- | ---- |
| 生命                     | +12  | +14  | +16  | +18  |
| 物攻 / 魔攻 / 物防 / 魔防 / 速度 | +2.4 | +2.8 | +3.2 | +3.6 |




#### 数值尺度说明

- 与[挡位表](#20-精灵能力值)对齐：
  - 生命挡位步长为 50
  - 五维挡位步长为 10
- 单条词条即使满金，也仍不足半档。
- 四件装备叠加后，整体提升通常约为半档到一档。

词条数值为浮点数，参与[能力值计算](#7-能力值计算)时不取整。

### 21.6 升级规则

每件装备拥有 **3 次升级机会**。每次升级流程如下：

1. 在本件装备的 3 条初始词条中，随机选中 1 条。
2. 该条词条再随机一次品质档（绿 / 蓝 / 紫 / 金）。
3. 将对应数值叠加到该词条当前数值上。

同一条词条可以被多次选中，多次叠加。

#### 示例：速度词条当前为绿档 +2.4


| 本次 roll 档 | 升级后                   |
| --------- | --------------------- |
| 绿         | +2.4 + 2.4 = **+4.8** |
| 蓝         | +2.4 + 2.8 = **+5.2** |
| 紫         | +2.4 + 3.2 = **+5.6** |
| 金         | +2.4 + 3.6 = **+6.0** |

## 22. 护盾

### 22.1 基本概念

护盾是一种**状态效果**，多个不同的护盾可以共存。持有护盾的精灵受到伤害时，先用护盾抵扣，未被抵扣掉的部分才扣除生命。

**来源归并**：同一来源精灵赋予的同一类护盾会**合并为一条护盾**（累积护盾量、共享上限、并刷新持续时间）；不同来源精灵赋予的护盾是**各自独立的多条护盾**，可以同时存在。

> 例：机械方方的「防火墙」与「便携防火墙」都是机械方方赋予的护盾，合并为同一条；而石化刺蜥蜴赋予的护盾与机械方方赋予的护盾来源不同，是两条独立护盾。

### 22.2 抵扣规则（多盾并行同时抵扣）

受到一次伤害时，**每一条护盾各自独立地扣除这次伤害的全额**，而非合并成一个总盾池：

- 每条护盾：`新护盾量 = max(0, 当前护盾量 − 本次伤害)`
- 实际扣除的生命：`掉血 = max(0, 本次伤害 − 抵扣前最厚的一条护盾)`

这会带来两个**有意为之**的特性：

1. 一次伤害会同时消耗每一条护盾，**被消耗的护盾总量可能大于这次伤害本身**（例：身上有两条盾时，30 点伤害会让两条盾各少 30，共消耗 60 点护盾）。
2. **多条薄盾不等于一条厚盾**：面对同一次大伤害，多条较薄的护盾会被一起打薄甚至打穿，抵挡效果不如把护盾集中在一条上。

> 例：某精灵拥有 A 护盾 100 点、B 护盾 50 点：
> - 受到 30 点伤害：A→70，B→20，不扣血。
> - 受到 80 点伤害：A→20，B 归零消失，不扣血。
> - 受到 120 点伤害：A、B 均归零消失，扣除 20 点生命（120 − 100）。

### 22.3 护盾也算“受到伤害”

拥有护盾时受到伤害，**即使这次伤害被护盾完全抵扣、没有扣除任何生命，仍然算作“受到伤害”**，会正常触发一切“受到伤害后 / 受击”类的效果与被动（包括持续伤害的每一跳）。

### 22.4 结算顺序

一次伤害的处理顺序为：

1. 伤害管线（基础伤害 → 暴击 → 增伤 / 减伤 → 承伤 → 限伤上限）算出**最终伤害值**；
2. **护盾抵扣**（见 22.2）；
3. 溢出部分扣除生命；
4. 致死判定与倒下结算。

即：**先结算减伤、限伤等，再用护盾抵扣**；护盾抵扣发生在扣血与致死判定之前。

### 22.5 持续时间与上限

护盾可以有持续时间和上限，具体由赋予它的技能决定。护盾量归零、或持续时间结束，则移除该护盾。

护盾的**授予量与上限均为实时计算**（例如“90% 施加者物攻”“上限 120% 施加者物攻”会随施加者当前属性实时变动）。但上限**只在获得 / 累积护盾的那一刻**作为闸门，用于限制这次能加到多少，**不会回溯削减已经存在的护盾量**。累积公式为：

```
新护盾量 = max(旧护盾量, min(旧护盾量 + 本次授予量, 当前上限))
```

含义：

- 若旧护盾量未达当前上限，则累加本次授予量，并以当前上限封顶；
- 若旧护盾量已达到或超过当前上限（例如上限因施加者属性下降而降低），本次授予**加不进去**，但已有护盾量**保持不变**，不会被削减。

已存在的护盾量只会因**受到伤害**或**持续时间结束**而减少。
